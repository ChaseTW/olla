# PenFunGo Design System｜Web v1

版本：1.0  
建立：2026-09-20  
狀態：目前網站的執行規範；品牌原始 CI 優先於本文件  
適用：靜態 MVP、後續 React 元件與新增品牌頁面

## 1. 設計命題

> 讓地方的知識，有被理解與接續的空間。

這是數位設計命題，不是已核定的品牌標語。網站的辨識不靠大量效果，而靠三件事：

1. 讓具體的人、材料、工作與關係被看見。
2. 用留白建立閱讀節奏，不把內容壓進公版卡片。
3. 讓每一頁依任務採用不同敘事，但共用同一套識別與操作方式。

如果把品牌名、照片與地名換掉後，畫面仍可原封不動套給其他公司，設計就還不夠具體。

## 2. 規範層級

| 層級 | 內容 | 效力 |
| --- | --- | --- |
| 原始品牌資產 | 正式 Logo、標準字、既有 CI 色彩與授權字型 | 最高；需使用核對過的原檔 |
| 數位設計系統 | 本文件的色彩角色、排版、版型、元件與動態 | 目前網站與 React 實作依據 |
| 頁面敘事 | C 共作長桌、A 工作桌、B 流域索引 | 依頁面任務使用，不混成一套效果 |
| 實驗與概念 | AI 圖像、候選標語、未核准文案 | 只能出現在明確標示的 preview |

## 3. Design tokens

### 3.1 品牌色

以下四個色值來自既有 CI 摘要；正式印刷或識別應用仍以原始 CI 檔為準。

| Token | HEX | 用途 |
| --- | --- | --- |
| `brand.blue` | `#024887` | 主要行動、閱讀路徑、局部品牌場景 |
| `brand.yellow` | `#E5E519` | 少量焦點、選中狀態、關鍵便箋 |
| `brand.stone` | `#8D8779` | 輔助色面；不作小字正文 |
| `brand.dark` | `#2F2725` | 正式識別深色；不是全站深底要求 |

### 3.2 數位中性色

| Token | HEX | 用途 |
| --- | --- | --- |
| `canvas` | `#FFFFFF` | 主要背景 |
| `ink` | `#14232B` | 標題與正文 |
| `muted` | `#526169` | 輔助文字 |
| `surface` | `#F6F8F7` | 有分組理由的淺底 |
| `milk` | `#F5F5F1` | 工作桌／材料場景的局部底色 |
| `fog` | `#EDF2F3` | 流域索引的次要色面 |
| `line` | `#CBD4D2` | 分隔與邊界 |

使用原則：

- 白底為主，CI 色用來建立路徑，不輪流把每一段塗滿。
- 黃色每個視窗最多承擔一個主要焦點；不要同時出現在所有元件。
- 長文保持淺底。深色只作局部轉折，不新增全站深色模式。
- 小字正文使用 `ink` 或 `muted`；`brand.stone` 對白底對比不足。
- 焦點不能只用黃色畫在白底，連結不能只靠顏色辨識。

### 3.3 CSS token 基線

```css
:root {
  --color-brand-blue: #024887;
  --color-brand-yellow: #e5e519;
  --color-brand-stone: #8d8779;
  --color-brand-dark: #2f2725;
  --color-canvas: #fff;
  --color-ink: #14232b;
  --color-muted: #526169;
  --color-surface: #f6f8f7;
  --color-milk: #f5f5f1;
  --color-fog: #edf2f3;
  --color-line: #cbd4d2;

  --space-page: clamp(1.375rem, 5.3vw, 5.25rem);
  --measure-body: 36rem;
  --container-wide: 80rem;
  --header-height: 4.875rem;
  --focus-ring: 3px solid var(--color-brand-blue);
  --ease-out: cubic-bezier(.2, .7, .2, 1);
}
```

現有靜態 CSS 使用較短的 token 名稱；React 重構時映射至上列語意名稱，不在 MVP 大量改名。

## 4. Typography

### 4.1 字型角色

- 網站目前：`"PingFang TC", "Noto Sans TC", sans-serif`。
- 既有 CI 記載：中文台北黑體、英文 BC Novatica CYR；是否載入網站需核對字型檔與授權。
- Logo 與標準字只能使用正式資產，不以 CSS 字型重打。

不要為了「有設計感」任意加入襯線標題、等寬眉標或裝飾英文。需要第二字型時，必須先說明它與品牌內容的關係。

### 4.2 字級

| Role | Desktop | Mobile | Line-height | Weight |
| --- | --- | --- | --- | --- |
| Display／首頁主標 | `clamp(4rem, 8vw, 7rem)` | 2.5–3.25rem | 1.05–1.15 | 500–600 |
| Page title | `clamp(3rem, 7vw, 6.125rem)` | 2.125–2.625rem | 1.13–1.2 | 500–600 |
| Section title | `clamp(2rem, 4vw, 4.25rem)` | 1.75–2.125rem | 1.25–1.4 | 500–550 |
| Lead | 1.25–1.5rem | 1.125–1.25rem | 1.7–1.8 | 400 |
| Body | 1.125rem | 1.0625rem | 1.8–1.9 | 400 |
| Navigation／button | .9375–1rem | .9375–1rem | 1.5 | 500 |
| Caption／meta | .8125–.875rem | .8125rem | 1.6 | 400 |

規則：

- 中文正文約 28–36 個全形字一行，最大閱讀欄寬約 `36rem`。
- 大標是構圖的一部分，不在每一頁重演首頁尺度。
- 不用縮小正文來塞內容；先編輯、分頁或移除重複資訊。
- 避免手動插入大量固定換行；手機自然重排。

## 5. Spacing and layout

基礎間距：4、8、12、16、24、32、48、64、80、96、120、144px。相鄰層級選擇應表達內容關係，不把每個區段套同一距離。

- 頁面水平邊距：`clamp(22px, 5.3vw, 84px)`。
- 寬內容容器：最多約 1280px。
- 正文欄：最多約 576px。
- Header：78px。
- 桌面基準：12 欄概念；首頁可 5/7，案例可 8/4，長文為窄側欄＋正文。
- 第一層 breakpoint：850px，雙欄回單欄、啟用手機選單。
- 第二層 breakpoint：520px，縮減區段 padding、表單回單欄。

對齊以左對齊為主。置中只用於需要共同注視的短句或單一儀式性時刻，不將長文置中。

## 6. Page narratives

### 首頁｜C 共作長桌

任務：接待、建立整體認識、讓訪客選擇下一步。

- 保留開放橫向場景、交錯角色與共同工作的空間感。
- 首頁資訊精煉；詳細方法、案例與品牌背景交給內頁。
- MVP 不放地方筆記，也不以其他內容填滿留下的空間。

### 關於｜A 工作桌

任務：透過人、手勢、材料、判斷與日常理解品牌。

- 允許尺度錯落與圖文遠近。
- 人物與團隊資料必須可核實。
- 溫暖來自具體工作，不來自泛黃濾鏡。

### 案例｜B 流域索引

任務：讓問題、角色、判斷、過程與結果可以被追讀。

- CI 藍用於路徑與層級，不必畫河流或地圖。
- 索引內容少時不用大型篩選器。
- 案例詳細頁可借用 A 的工作現場語言。

### 合作方式與聯絡

任務：把能力轉成可理解的合作情境，提供真實可完成的下一步。

- 延續 C 的接待感，但以清楚資訊和狀態為優先。
- 沒有真正 endpoint 時不得呈現假成功表單。

### 地方筆記

V1 不部署。V1.1 延續 B 的內容索引，文章頁以正文、圖說、來源和關聯閱讀優先。

## 7. Components

所有元件都有可見 focus、鍵盤行為、觸控尺寸與 reduced-motion 版本。

### Header

- 品牌識別連到首頁。
- 桌面導覽保持 4 個主要目的頁加一個 CTA。
- 手機 850px 以下使用按鈕展開；`Escape` 關閉並把焦點還給按鈕。
- 當前頁使用 `aria-current="page"`。

### Links and buttons

- Primary button：藍底白字、最小高度 48–52px、使用清楚動詞。
- Secondary link：底線／底部邊界等非顏色線索；名稱說明目的頁。
- 外部或深入閱讀箭頭只在能表達方向時使用，不把箭頭當每個 CTA 的裝飾。

### Project record

- 影像／色面和文字交錯，但閱讀 DOM 順序保持一致。
- 卡片不共用一種圓角、陰影與尺寸；依案例內容決定比例。
- 每張案例必须能回答「屏方根做了什麼」，而不只是展示完成品。

### Form

- 永久可見 label；placeholder 不取代 label。
- 必填、格式錯誤、送出中、成功與失敗都有獨立狀態。
- 成功訊息必须有實際收件依據。
- 欄位有適當 `autocomplete`；資料用途與保存說明在送出前可見。

### Footer

- 只放公開目的頁、正式聯絡／法律資訊與版權。
- 不放 Dokki、設計手冊、preview 說明或未部署路由。

## 8. Images

- 主題順序：人與關係 → 工作現場 → 材料／工具 → 場域 → 完成品。
- 一組內容盡量包含環境遠景、關係中景與工序細節。
- 保留自然光與遮蔭，不全站調黃或去飽和。
- 圖說包含可核實的人物、地點、時間、攝影與使用權；無資料不補造。
- AI 概念圖只能表達光線、構圖與情緒，不可作案例、團隊或屏東現場證據。
- 文化圖紋、祭儀與族群物件不可直接變成裝飾。

## 9. Motion

- 一頁最多一個主要非操作觸發的動態命題。
- 操作回應：160–240ms。
- 一次性進場：400–600ms；位移不超過約 12px。
- 使用 `cubic-bezier(.2,.7,.2,1)` 或簡單 ease-out。
- 不使用捲動劫持、長時間 pin、自動播放聲音或每段相同淡入。
- `prefers-reduced-motion: reduce` 取消非必要 animation／transition；正文初始就可見。

## 10. Accessibility and quality floor

- 正文與互動文字至少符合 WCAG AA 對比。
- 全站保留「跳到主要內容」。
- Focus ring 預設為 3px 品牌藍；藍底改用品牌黃或白。
- HTML heading 不跳級，頁面只有一個主要 `h1`。
- 圖片有內容性的 alt；純裝飾圖使用空 alt。
- 200% 文字放大與 320px 寬度不阻擋閱讀和操作。
- 內容不能依賴動畫完成才出現。

## 11. Anti-template review

交付前逐項檢查：

- 是否出現大量相同圓角、陰影與等尺寸卡片？
- 是否用泛米色、南國濾鏡或觀光符號代替屏東的具體內容？
- 是否每段都有無意義的英文眉標、編號或箭頭？
- 是否同一頁同時使用 A／B／C 三套主角效果？
- 是否只有完成品，沒有人的判斷、工序與合作關係？
- 是否為了填版而加入未核准文案、照片或功能？

若答案為是，先移除一項裝飾，再重新確認內容層級。

## 12. React implementation contract

React 元件必須使用本文件的語意 token，不將頁面局部 hex、spacing 或 transition 散落在 JSX。

建議第一層元件：

- `SiteHeader`
- `SiteFooter`
- `PageHero`
- `EditorialPair`
- `ProjectRecord`
- `CaseMeta`
- `CallToAction`
- `ContactForm`
- `SkipLink`

頁面敘事以 layout composition 實作，不為 A／B／C 各複製一套 Header、Button 或 typography。

任何新 token 必須先回答：它解決的是新語意，還是單一頁面的臨時數值？只有前者進入系統。
